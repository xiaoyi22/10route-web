# 模型检测配置

## 检测间隔

间隔允许 1～10080 分钟的整数，拒绝空值、小于 1 的值和小数。不会因修改页面下限而自动改变当前检测计划。

## 智商检测思考强度

- 自动检测配置在每个模型旁提供思考强度选择，仅在该模型已勾选智商检测时可编辑。
- 默认选项为“沿用网关”，不添加思考覆盖参数，保持原有供应商设置和模型默认行为。
- 后端提供档位列表时按模型展示；缺少列表或返回 null 时允许手动选择 none、minimal、low、medium、high、xhigh、max 等通用档位，并明确提示模型支持尚未确认。网关或上游可能忽略或拒绝该档位，手动选择不代表模型具备此能力。
- 各模型支持的档位可能不同，例如 `minimal`、`low`、`medium`、`high`、`xhigh`、`max`；关闭思考和二态思考也仅在后端返回对应档位时展示。
- 单次智商检测初始沿用该模型自动检测配置的档位，可以临时调整，不修改自动检测计划。
- 思考强度不应用于模型测活；检测详情保留本轮档位。历史没有档位字段时显示“未记录（旧记录）”。
- 更改思考档位后，不将不同档位的 IQ 得分直接用于分数变化比较。

## 接口字段

`GET /api/iq-monitor` 的供应商目录新增 `thinkingLevels`：模型 ID 到可选档位数组的映射。空数组表示模型不支持，不能新增覆盖；字段缺失或 null 表示未提供能力信息，可手动选择通用档位。响应通过 `capabilities.modelThinking: true` 声明支持保存自动检测思考强度。

`PUT /api/iq-monitor` 的供应商选择中新增可选 `modelThinking`：模型 ID 到指定档位的映射。默认沿用网关时删除对应条目；旧配置不必迁移。后端在写入前校验模型与档位，拒绝不支持的选择。

保存非默认档位前，页面检查后端保存能力；旧后端未声明支持时阻止写入整个计划并提示升级，不会静默丢弃档位。支持保存的后端必须在 PUT 响应及随后 GET 回读中保留完整档位映射，否则页面显示错误、保留草稿，不显示保存成功。回读失败或检测到丢失时，其他计划设置可能已写入，需要刷新核对。单次检测不依赖该保存能力声明。

自动检测执行与单次检测均复用网关已有的 `model(level)` 机制，由统一思考转换逻辑生成各供应商所需的请求字段。自动检测仍按原始模型 ID 选择账号，历史模型 ID 不带档位后缀。
