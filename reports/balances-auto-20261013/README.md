# 余额与配额自动更新开关

已实现并验证，于 2026-10-13 16:40 随完整版本上线。

## 行为

- 页面标题旁新增“自动更新”开关，默认开启；开关状态保存在当前浏览器的 `balancesAutoRefresh` 中，重载和离开后返回都会保留。
- 查看账号配额时每 1 分钟自动请求配额接口；查看供应商余额时每 5 分钟自动请求余额接口。自动更新只请求当前标签。
- 离开余额与配额页面时，组件卸载并清除计时器和可见性监听；其他页面不会因该功能继续发起余额或配额请求。
- 浏览器标签隐藏时清除计时器，恢复可见后重新等待一个完整周期，不补发后台期间的请求。
- 关闭开关停止自动查询；进行中的余额/配额请求和余额设置保存期间暂停计时，避免重复请求。
- 保留进入页面时读取两个接口、切换标签不立即重查、手动刷新两个接口的原有行为。已发出的上游请求可能完成，停止自动更新不等于撤销已发出的请求。
- 自动查询不携带 `force=1`，手动刷新仍携带 `force=1`。当前后端汇总接口缓存有效期为 5 分钟，因此配额“一分钟”表示页面查询间隔，实际数据更新时间以接口返回的 `checkedAt` 为准；本次未调整后端缓存和上游访问限制。
- 原始 UI 的账号配额刷新常量是 60000 ms，Claude 单独为 600000 ms；原始余额页面为 300000 ms。本次恢复页面查询节奏，未声称恢复原始 UI 对每种供应商的独立上游轮询实现。

## 改动

- `src/pages/BalancesPage.jsx`：增加持久化开关、页面内可见性计时与独立标签刷新版本。
- `tests/balances-auto-browser.mjs`：隔离浏览器验证开关、持久化、手动刷新、配额一分钟、余额五分钟、慢请求不叠加、后台暂停、路由离开停止及返回。
- `tests/balances-auto-live-browser.mjs`：真实网关及构建产物验证，无模拟接口。
- 没有修改后端代码，也没有新增依赖；保留供应商批量操作和请求日志速度等待上线改动。

## 验证

- `npm.cmd test`：125 项全部通过。
- `npm.cmd run build`：通过。
- 原有 `tests/balances-browser.mjs`：余额/配额切换、独立搜索、键盘、重载、手动刷新及深浅主题七种屏宽通过。
- 新增隔离浏览器测试：构建产物配合内存演示接口，7 组断言通过，覆盖重载持久化、慢请求及各项暂停条件；深浅主题四种屏宽均无页面溢出和控制台错误。
- 开发服务上的计时测试先出现重载后页面未初始化的超时，随后出现虚拟时钟暂停目标落在过去的错误；清理开发服务时还发现 Vite 文件监听因 `.tmp-pv.mjs` 被占用而报 EBUSY。重载超时的原因未单独确认。改用构建产物，并使用当前虚拟时间之后的暂停目标，全部断言最终通过；隔离测试服务已关闭。
- 真实数据验收：构建预览 `http://127.0.0.1:4333` 连接真实后端 `192.168.11.150:20128`；健康接口确认 `better-sqlite3`，认证确认非演示模式。
- 健康、认证状态、登录、页面、余额接口、配额接口和一分钟自动配额请求均为 HTTP 200；关闭、隐藏和离开页面后的请求计数保持不变。
- 深浅主题及 320/375/768/1440 屏宽通过；无浏览器控制台错误、无账号配置或手动强刷等业务写入。
- 部分真实账号会返回上游配额错误（如 Qoder 401），页面如实展示；HTTP 200 验收不代表每个上游账号都能查询成功。
- 源码差异空白检查和两份浏览器脚本语法检查通过。
